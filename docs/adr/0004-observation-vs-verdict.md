# ADR-0004 · 관측과 판정을 분리하고 승격을 거친다

- 상태: **채택**
- 일자: 2026-09-05
- 관련: `SDD.md` §4 · `AGENTS.md` INV-8

## 맥락

가장 단순한 설계는 주간 스캔 결과를 그대로 공개 화면에 붙이는 것이다. 테이블 하나, 조회 하나로 끝난다.

문제는 **공표되는 수치는 되돌릴 수 없다**는 점이다. 어떤 기관이 "지난주에는 열려 있다고 하더니 이번 주에는 닫혔다고 한다"고 물으면, 우리는 그 변동이 실제 정책 변경인지 서버 일시 장애인지 답할 수 없다. 실측에서 확인했듯 타임아웃은 상시 발생한다.

한 번의 관측으로 기관의 상태를 단정하는 것은 측정이 아니라 **스냅샷**이다.

## 결정

관측(`tech_scans`)과 판정(`verdicts`)을 별도 테이블로 분리하고, **2주 연속 동일 결과일 때만 판정으로 승격**한다.

- 승격 규칙: 최근 2회 스캔의 `(robots_verdict, undetermined_reason)` 이 같으면 `verdicts` 를 갱신한다.
- 다르면 **갱신하지 않는다.** 직전 판정이 유지되고 `change_pending = true` 가 선다.
- 공개 화면은 `verdicts where published` 만 읽는다. `tech_scans` 를 직접 렌더하지 않는다.
- DB 제약: `check (consecutive_weeks >= 2)`

## 근거

**흔들리는 값을 공개 화면에 흘리지 않는다.** 대신 운영자가 흔들리는 도메인을 목록(`/admin/scans`)으로 본다. 이것은 숨기는 것이 아니라, *아직 말할 준비가 되지 않은 것을 말하지 않는 것*이다.

이 구조는 세 가지를 동시에 해결한다.

1. **일시 장애가 판정을 뒤집지 않는다.** 한 주 타임아웃이 났다고 개방→판정불가로 공표가 바뀌지 않는다.
2. **시계열이 살아남는다.** `tech_scans` 는 매주 전부 남으므로, 나중에 승격 규칙을 바꾸더라도 과거 관측으로 재계산할 수 있다. 규칙을 데이터에 굽지 않았다.
3. **사전 통지가 가능해진다.** `verdicts.published` 를 `false` 로 두고 통지 기간을 거친 뒤 일괄 공개할 수 있다(FR-24). 관측과 판정이 한 테이블이었다면 "아직 공개하지 않은 판정"이라는 상태를 만들 자리가 없다.

2주라는 값은 스캔 주기(주 1회)에서 나온다. 3주는 상태 변화 반영이 너무 느리고, 1주는 승격이 아니다. 이 값은 `verdicts.consecutive_weeks` 로 기록되므로, 나중에 조정하더라도 **어떤 판정이 몇 주 근거로 나왔는지** 추적된다.

## 결과

- 상태 변화가 화면에 뜨기까지 최대 2주 지연된다. 기관이 조치한 뒤 "왜 아직 반영이 안 되느냐"고 물을 수 있다. 기관 대시보드(FR-12)에는 **미승격 관측을 함께 보여준다** — 공개 화면과 자기 대시보드의 시차를 그 기관은 알 수 있어야 한다.
- 승격 잡(`verdict-promote`)이 실패하면 판정이 낡는다. 실행 실패를 알림 대상으로 둔다.
- `tech_scans` 는 최소 3년 보존한다(NFR-7). 판정만 남기고 관측을 지우면 재계산 능력을 잃는다.

## 되돌리는 조건

- 상태 변화의 실시간성이 제품 가치에 결정적이라는 근거가 나오면 승격 주차를 재검토한다. 다만 **1주로 내리는 것은 승격 폐지와 같으므로**, 그 경우 이 ADR을 폐기하고 대체 ADR을 쓴다.
