# 03 관측 실행

## 1. 프록시 지표 선언

조회로 받은 응답은 **사용자가 실제로 보는 답과 같지 않습니다.** 접속 경로,
개인화, 지역, 시점이 다릅니다.

모든 산출물에 이 선언을 붙입니다. `output` 레코드의 `proxy_notice`는
필수 필드이며 비울 수 없습니다.

## 2. 고정하는 것

판본을 여는 시점에 아래를 고정하고, **판본이 끝날 때까지 바꾸지 않습니다.**

```
모형 식별자와 판본
호출 파라미터 (온도·길이 등)
반복 횟수
언어
앞말 지시문
조회 기간
```

`data/registries/run_profile.json`에 기록하고, 관측 레코드마다
`run_profile_id`로 참조합니다.

### 2.1 하지 않는 것

- **앞말 지시문을 기관마다 다르게 꾸미지 않습니다.** 답이 잘 나오게 하려고
  문장을 다듬는 순간 관측이 아니라 시연이 됩니다
- **표본 파라미터를 결과를 보고 조정하지 않습니다.** 조정했다면 그 판본은
  버리고 다시 엽니다
- 실패한 호출을 조용히 재시도해 성공만 남기지 않습니다. 재시도는 모두 기록합니다

## 3. 수집 규율

### 3.1 로봇 규칙

- 로봇 규칙을 어기고 얻은 자료를 쓰지 않습니다
- **검색 결과 페이지를 자동 수집하지 않습니다**
- 로봇 규칙 확인 결과를 수집 로그에 남깁니다. 확인하지 않은 수집은 무효입니다
- 로봇 규칙의 적용 범위는 호스트·프로토콜·포트 단위입니다. 경로 단위로
  다른 호스트의 규칙을 적용하지 마십시오

자세한 것은 `policy/robots_policy.md`.

### 3.2 접근 간격

기관 자산에 대한 직접 조회는 간격을 두고, 동시 연결 수를 제한합니다.
구체 값은 운영 설정이며 이 저장소가 정하지 않습니다.

## 4. 응답의 처리

```
1. 응답 원문을 그대로 저장한다        → response_record
2. 원문에서 값과 주소를 꺼낸다         → observation.extracted
3. 꺼낸 값을 원장과 대조해 판정한다     → verdict
```

1과 2를 합치지 마십시오. 2를 다시 돌려야 할 일이 반드시 생깁니다.

### 4.1 추출과 판정의 분리

| 단계 | 언어 모형 | 규칙 |
|---|---|---|
| 추출 | 쓸 수 있음 | 쓸 수 있음 |
| 판정 | **쓰지 않음** | 규칙과 원장 대조만 |

`verdict.judged_by`는 `rule`만 허용합니다. 스키마가 강제합니다.

### 4.2 본문 주소와 근거 목록

따로 셉니다. 합산한 수치를 만들지 마십시오.

```
body_urls      응답 본문 안에 나타난 주소
citation_urls  응답이 별도로 제시한 근거 목록
```

### 4.3 거절은 결측이 아닙니다

모형이 답을 거절했다면 그것은 관측값입니다. `N5`로 기록하고 결측 처리하지
않습니다. 거절 원문도 그대로 보존합니다.

## 5. 반복과 불안정

같은 문항을 여러 번 조회하면 답이 갈릴 수 있습니다.

- 회차별 응답을 **모두** 보존합니다. 대표값 하나만 남기지 않습니다
- 회차 사이에 답이 갈린 문항은 `unstable: true`로 표시합니다
- 불안정한 문항의 판정을 확정으로 내보내지 않습니다

## 6. 역점사업 관측의 추가 규율

- **단계**는 관측 시점의 원장 상태를 함께 기록해야 판정이 가능합니다.
  `project_record.stage_as_of`를 관측과 같은 날짜로 맞추십시오
- 원장 자체가 낡아 있는 경우가 있습니다. 이때는 답이 아니라 원장을 고쳐야
  하며, `ledger_stale: true`로 표시하고 판정을 내리지 않습니다.
  **원장이 틀린 것을 우리가 대신 판단해 고쳐 쓰지 않습니다**
- 같은 이름의 다른 대상이 답을 가져간 경우 `name_collision`에 관측된 대상을
  기록합니다. 관측하지 않으면 드러나지 않는 현상입니다
