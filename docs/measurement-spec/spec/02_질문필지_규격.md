# 02 질문 필지 규격

문항 집합이 임의로 정해지면 그 위에 올린 모든 수치가 임의가 됩니다.
문항을 추가·수정·삭제하려는 사람은 이 문서를 먼저 읽어야 합니다.

---

## 1. 여섯 요건

문항 하나가 갖추어야 하는 성질입니다.

| # | 요건 | 뜻 | 위반하면 |
|---|---|---|---|
| 1 | 배타성 | 다른 문항과 사실 범위가 겹치지 않음 | 같은 사실을 두 번 세게 됨 |
| 2 | 경계 선언 | 무엇까지 묻고 무엇은 묻지 않는지가 문항에 적혀 있음 | 판정자마다 다르게 읽음 |
| 3 | 지번 영속 | 한 번 부여한 지번을 바꾸지 않음 | 판본 사이 비교가 끊김 |
| 4 | 정본 귀속 | 그 사실의 정본을 가진 주체가 지정됨 | 고칠 사람을 못 찾음 |
| 5 | 입도 동형 | 기관이 달라도 같은 크기의 사실을 물음 | 비교가 성립하지 않음 |
| 6 | 출처 보유 | 법정 사무 또는 의무 공개 문서에서 도출됨 | 우리가 의무를 창설하게 됨 |

## 2. 다섯 관문

문항을 집합에 넣기 전에 순서대로 통과시킵니다. 하나라도 걸리면 넣지 않습니다.

```
1. 출처 관문   법정 사무 또는 의무 공개 문서에 근거가 있는가
               → 기관의 자기 기록만 근거인 문항은 공통 코어에 넣지 않는다
                 (개별 확장 전용)

2. 원장 관문   답이 맞는지 대조할 문서가 있는가
               → 없으면 값형이 아니라 서술형으로 분류한다

3. 귀속 관문   그 사실의 정본 주체를 지목할 수 있는가
               → 지목할 수 없으면 격자의 대상은 되나 처방 대상은 아니다

4. 입도 관문   기관이 달라도 같은 크기의 사실인가
               → 아니면 계열 코어 또는 개별 확장으로 내린다

5. 지번 관문   기존 지번과 사실 범위가 겹치지 않는가
               → 겹치면 기존 문항을 고치고 새 지번을 만들지 않는다
```

## 3. 세 지적

| 지적 | 대상 | 비교 가능 범위 |
|---|---|---|
| 공통 코어 | 모든 기관 | 동류 집단 안에서 비교 가능 |
| 계열 코어 | 같은 계열에 속한 기관 | 같은 계열 안에서만 비교 가능 |
| 개별 확장 | 한 기관 | **비교 불가.** 같은 기관의 앞 시점과만 |

계열 사이를 비교하지 않습니다. 계열별 결과를 합산하지 않습니다.

## 4. 역점사업 지번의 특례

역점사업 문항은 **개별 확장**에 속합니다. 기관마다 사업이 다르므로 입도 관문을
통과하지 못하기 때문입니다. 다만 다른 개별 확장과 달리 다음이 성립합니다.

- 출처 관문 통과: 재정 공시의 주요 투자사업 항목이 의무 공개 문서입니다
- 원장 관문 통과: 예산서·투자심사·고시·검사조서가 원장 노릇을 합니다
- 귀속 관문 통과: 소관 부서가 이미 지정되어 있습니다

### 4.1 대상 요건

사업 하나를 문항 집합에 넣으려면 셋을 모두 채워야 합니다.

1. 예산이 편성되어 있을 것
2. 소관 부서가 지정되어 있을 것
3. 공식 사업명이 확정되어 있을 것 — **가칭 단계의 사업은 넣지 않습니다**

가칭에 정본을 만들면 나중에 이름이 둘 남아 답이 갈라집니다.

### 4.2 한 사업에 붙는 여섯 물음

`data/questions/project_template.json`의 템플릿으로 생성합니다.
지번은 `PRJ-<기관 손잡이>-<사업 일련>-<물음 번호>` 형태로 만듭니다.

| 물음 | 유형 | 원장 |
|---|---|---|
| 존재 | 값형 | 예산서 사업명 |
| 소재 | 값형 | 실시계획 고시의 위치 |
| 단계 | 값형 | 고시·착공 서류·준공검사조서 |
| 규모·일정 | 값형 | 투자심사 결과·예산서·공기 |
| 이용 | 서술형 | — |
| 주체 | 값형 | 사무 분장 규칙 |

**단계가 중심입니다.** 나머지는 한 번 적어두면 오래 가지만 단계는 계속 바뀝니다.

## 5. 문항을 고칠 때

```
사실 범위를 넓히거나 좁힘   → 기존 지번 유지, revision 올림, 변경 사유 기록
전혀 다른 사실을 묻게 됨     → 기존 지번 폐기(retired), 새 지번 부여
표현만 다듬음               → revision 올림
```

폐기한 지번을 다시 쓰지 않습니다. 판본 사이 비교가 끊깁니다.

## 6. 문항 파일의 필수 항목

`schema/question.schema.json` 참조. 빠뜨리기 쉬운 것만 적습니다.

- `boundary` — 무엇은 묻지 않는지를 반드시 적습니다 (요건 2)
- `ledger` — 값형이면 필수. 없으면 서술형이어야 합니다 (관문 2)
- `owner_role` — 정본 주체의 역할. 기관 실명이 아니라 역할명 (관문 3)
- `difficulty` — `D0`이면 무료 도구로 확인 가능. **청구하지 않습니다**
- `sensitivity` — `restricted`이면 공표 경로에서 제외됩니다
