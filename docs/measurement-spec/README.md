# 지자체 정보 상태 측정 — 규격 저장소

이 저장소는 **무엇을 어떻게 관측하고 어떤 형태로 기록할 것인가**를 정의합니다.
관측 대상은 지방자치단체가 공개하고 있는 정보의 상태이며, 장소 브랜드나 기관의
역량을 재지 않습니다.

측정 시스템을 구현하는 개발팀은 이 저장소의 스키마와 코드표를 **단일 출처**로
삼아야 합니다. 애플리케이션 코드 안에 문항 목록이나 코드값을 다시 적지 마십시오.

---

## 0. 저장소에 적지 않는 것 — 먼저 읽으십시오

다음은 취향이나 관행이 아니라 **지켜야 하는 제약**입니다.

### 0.1 산식을 이 저장소에 적지 않습니다

지표의 계산식, 가중치, 임계값, 구간 경계, 정규화 방법은 이 저장소의 어떤
파일에도 적지 않습니다. 파일명, 디렉터리명, 클래스명, 함수명, 변수명, 주석,
커밋 메시지, 이슈 제목에도 적지 않습니다.

산식은 `sealed/` 아래에 두되 **버전 관리에 포함하지 않습니다**(`.gitignore` 참조).
이 저장소는 산식이 들어갈 자리에 **인터페이스만** 정의합니다.

> 이유: 출원 중인 사항의 공개 범위가 아직 확정되지 않았습니다.
> 공개된 자리에 적힌 산식은 되돌릴 수 없습니다.

### 0.2 만들 수 없는 산출물이 있습니다

<!-- lint:allow-banned:start -->

| 만들지 않는 것 | 왜 |
|---|---|
| 기관별 총점 | 성격이 다른 관측을 더하면 근거가 사라집니다 |
| 기관 순위표 | 분위 밴드로만 표현합니다 |
| 등급 (A·B·C 또는 우수·보통·미흡) | 순위의 다른 이름입니다 |
| 항목별 가중치 | 총점을 만드는 장치입니다 |
| 빈칸 개수 합계 | 부재의 양으로 만든 서열표가 됩니다 |
| 미래 목표치·개선 예측치 | 관측으로 뒷받침되지 않습니다 |

<!-- lint:allow-banned:end -->

스키마에는 이 값들을 담을 **필드 자체가 없습니다**. 규칙으로 막는 것보다
서식으로 막는 편이 오래갑니다. `tools/validate.py`가 금지 키를 검사합니다.

### 0.3 판정에 언어 모형을 쓰지 않습니다

언어 모형은 **응답 원문에서 값을 꺼내는 데까지만** 씁니다. 꺼낸 값이 맞는지
틀렸는지는 규칙과 원장 대조로만 정합니다. 판정 레코드의 `judged_by`는
`rule` 이외의 값을 허용하지 않습니다.

### 0.4 응답 원문을 요약해 저장하지 않습니다

관측한 응답은 전량 원문으로 보존합니다. 재현 자료로 납품해야 하기 때문입니다.
`response_record`에는 요약 필드가 없습니다.

## 1. 디렉터리

```
작업지시서.md   구현팀에 전달하는 작업 지시. 도해 포함
spec/          규격 문서. 사람이 읽는 기준
data/
  questions/   문항 지식 소스
  codes/       코드표
  registries/  원장 출처·계열 배정 등록부
schema/        JSON Schema. 기계가 읽는 기준
fixtures/      표본 레코드. 스키마 이해용
policy/        수집·보존·표현 규율
tools/         검증 도구
docs/          작업지시서의 도해
sealed/        산식 구현 자리. 버전 관리 제외
```

## 2. 시작하기

```bash
python3 tools/validate.py          # 스키마 검증 + 금지 키·표현 린트
python3 tools/validate.py --strict # 경고도 실패로 취급
```

수정한 파일을 올리기 전에 반드시 통과시키십시오.

## 3. 읽는 순서

0. `작업지시서.md` — 전체 얼개와 착수 순서
1. `spec/00_용어.md` — 용어를 먼저 맞춥니다
2. `spec/02_질문필지_규격.md` — 문항이 왜 그렇게 생겼는지
3. `schema/observation.schema.json` — 관측 한 건의 모양
4. `spec/04_판정_규칙.md` — 무엇을 어긋남이라 부르는지
5. `spec/05_산출물.md` — 밖으로 나가는 형태

## 4. 이 저장소가 정하지 않는 것

- 어떤 모형을 쓸 것인가 (운영 설정의 몫)
- 저장소 기술 선택 (구현팀의 몫)
- 화면과 보고서 디자인 (별도 규격)
- 지표의 계산 방법 (§0.1)
