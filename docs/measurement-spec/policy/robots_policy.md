# 수집 규율

## 1. 지키는 것

- **로봇 규칙을 어기고 얻은 자료를 쓰지 않습니다.** 얻은 뒤에 알게 되었다면
  그 자료를 버리고 관측을 다시 합니다
- **검색 결과 페이지를 자동 수집하지 않습니다**
- 로봇 규칙 확인 결과를 수집 로그에 남깁니다. **확인하지 않은 수집은 무효입니다**

`observation.access_state.robots_checked`가 `false`인 관측은 판정으로
넘기지 마십시오.

## 2. 로봇 규칙의 적용 범위

적용 범위는 **호스트·프로토콜·포트 단위**입니다.

```
https://example.go.kr/robots.txt
  → https://example.go.kr 의 모든 경로에 적용
  → http://example.go.kr (다른 프로토콜) 에는 적용되지 않음
  → https://sub.example.go.kr (다른 호스트) 에는 적용되지 않음
```

한 호스트의 규칙을 다른 호스트에 적용하지 마십시오. 흔한 구현 실수입니다.

## 3. 차단과 색인 거부는 서로 상쇄됩니다

수집을 막으면서 동시에 색인 거부 표시를 다는 설정은 **서로 취소됩니다.**
수집이 막혀 있으면 색인 거부 표시를 읽을 수 없기 때문입니다.

기관 자산에서 이 조합을 발견하면 관측 기록에 남기고, 처방 목록에 올립니다.
이것은 기관이 고칠 수 있는 문제입니다(`N1` 계열).

## 4. 접근 방식

- 기관 자산에 대한 직접 조회는 간격을 두고 동시 연결 수를 제한합니다
- 식별 가능한 사용자 문자열을 씁니다. 사람인 척하지 않습니다
- 조회 실패를 우회하려고 접근 방식을 바꾸지 않습니다. 실패는 관측값입니다

## 5. 봇과 사람에게 다른 내용을 주지 않습니다

이것은 우리가 지키는 규율인 동시에 **기관에 권하는 규격**입니다.
처방에 이 내용을 넣을 때, 기관이 반대로 알아듣지 않도록 적으십시오 —
"기계에만 잘 보이게 하라"가 아니라 "같은 원장에서 두 가지로 내보내라"입니다.

## 6. 수집하지 않는 것

| 대상 | 왜 |
|---|---|
| 검색 결과 페이지 | 자동 수집 대상이 아닙니다 |
| 로그인이 필요한 영역 | 공개된 상태가 아닙니다 |
| 개인정보가 포함된 화면 | 관측 대상이 아닙니다 |
| 로봇 규칙이 막은 경로 | §1 |
