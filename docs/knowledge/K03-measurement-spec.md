## M-1 · 기술 접근성 (Layer 1)

### M-1.0 수행 원칙 — 예의 있는 수집

공공 서버에 부하를 주지 않는 **최소 요청**으로 수행한다.

| 규칙 | 값 |
|---|---|
| 주기 | 도메인당 **주 1회** (DB 유니크 제약으로 보장) |
| 같은 호스트 요청 간격 | 최소 5초 |
| 타임아웃 | 10초 |
| 리다이렉트 | 3회까지 |
| User-Agent | `KPlaceLabBot/1.0 (+https://kplacelab.kr/bot; contact@kplacelab.kr)` |
| 한 도메인당 요청 수 | 최대 4 (robots · 홈 · sitemap HEAD · TLS) |

**`robots.txt` 가 우리 UA를 거부하면 그 사실만 기록하고 더 이상 요청하지 않는다.**

**차단을 우회하지 않는다.** UA 위장, 프록시 회전, 캡차 우회, 헤드리스 브라우저 대체 — 전부 금지. 이것은 기술 선택이 아니라 존립 조건이다.

### M-1.1 robots.txt 판정 — 4분

```
1. 응답을 얻지 못함 (타임아웃 · 네트워크 오류 · 5xx)
       → undetermined / timeout
2. 404
       → no_file
3. 200 이지만 본문이 HTML로 보임
       → undetermined / malformed
4. 200 이고 텍스트이지만 그룹 구조를 읽을 수 없음
       → undetermined / parse_fail
5. 정상 파싱됨
       대상 AI 수집기별로 규칙을 해석한다
       전부 disallow_all   → blocked_all
       일부 disallow_all   → blocked_selective
       그 외               → open
```

`shared_domain` 은 스캐너가 아니라 **단위 마스터**에서 결정된다. B형 단위는 스캔 대상이 아니며, 화면에서 소관 시·도의 값을 참조하되 병기 문구를 붙인다.

#### HTML 판별 기준

본문 첫 1KB 안에 `<!doctype`, `<html`, `<head`, `<body` 중 하나라도 있으면 HTML로 본다. 대소문자 무시.

> 실측에서 확인된 실제 사례다(경기 GGFEZ). 서버가 존재하지 않는 경로에 대해 홈페이지를 반환하는 soft-404 설정이며, 크롤러별로 해석이 갈려 결과가 불안정해진다.

#### 그룹 해석 규칙

표준 robots.txt 해석을 따른다.

1. `User-agent:` 로 그룹이 시작된다. 연속된 `User-agent:` 는 같은 그룹에 속한다.
2. 대상 UA와 **정확히 일치**(대소문자 무시)하는 그룹이 있으면 그것을 쓴다.
3. 없으면 `*` 그룹을 쓴다.
4. `*` 그룹도 없으면 `미지정` — 개방으로 본다.
5. 그룹 안에 `Disallow: /` 가 있으면 `disallow_all`.
6. 다른 `Disallow:` 경로만 있으면 `partial` — **차단으로 세지 않는다.**

`Allow:` 와 `Disallow:` 의 경로 우선순위(최장 일치)는 v1.0에서 판정에 반영하지 않는다. 루트 전면 차단 여부만 본다. 이 단순화를 명세에 명시한다.

#### 대상 AI 수집기 목록

`seed/ai_agents.json` 이 원본. v1.0 기준:

```
GPTBot            OAI-SearchBot     ChatGPT-User
ClaudeBot         Claude-User       anthropic-ai
PerplexityBot     Perplexity-User
Google-Extended   Applebot-Extended
CCBot             Bytespider
```

> **목록 변경은 `method_version` 을 올린다.** 수집기가 추가되면 과거 판정과 비교할 수 없기 때문이다. 이것이 목록을 코드가 아니라 시드에 두는 이유다.

### M-1.2 Sitemap

| 판정 | 조건 |
|---|---|
| `있음` | `robots.txt` 에 `Sitemap:` 선언이 있고, 그 URL이 HEAD 200 |
| `선언되었으나 접근 불가` | 선언은 있으나 HEAD 실패 |
| `없음` | 선언 없음 |

`no_file` (robots 404) 인 경우 **자동으로 `없음`** 이다 — 선언할 자리 자체가 없다. 이것이 404를 개방으로만 볼 수 없는 이유다.

### M-1.3 meta robots

메인 페이지 HTML의 `<meta name="robots" …>` 원문을 기록하고, `noindex` 포함 여부를 판정한다. robots.txt가 우리 조회를 거부하면 **수행하지 않는다**(값은 `null`).

### M-1.4 구조화 데이터 (JSON-LD)

메인 페이지의 `application/ld+json` 블록을 세고, 파싱 가능 여부와 `@type` 목록을 기록한다.

| 판정 | 조건 |
|---|---|
| `정상` | 1개 이상, 전부 파싱 가능 |
| `문법 오류` | 존재하나 파싱 실패 |
| `타입 오표기` | 파싱은 되나 공공기관에 부적합한 타입만 존재 |
| `없음` | 0개 |

공공기관 권장 타입은 별도 목록으로 관리한다(`GovernmentOrganization`, `GovernmentService`, `Place`, `Event`, `FAQPage`, `NewsArticle`, `OpeningHoursSpecification`, `ContactPoint`).

### M-1.5 TLS

인증서 체인 검증 성공 여부와 만료일을 기록한다.

> **주의** — 프록시를 경유하는 환경에서는 인증서가 프록시의 것으로 관측되어 만료일이 무의미해진다. **스캐너는 직접 egress가 가능한 환경에서만 실행한다.** 프록시 경유가 감지되면 `tls_ok` 를 `null` 로 남기고 판정하지 않는다.

### M-1.6 승격 규칙

**단발 스캔은 판정이 아니다.** 최근 2회 스캔의 `(robots_verdict, undetermined_reason)` 이 동일할 때만 공표 가능한 판정으로 승격한다. 다르면 직전 판정이 유지되고 운영 대시보드에 `흔들림`으로 표시된다. → [ADR-0004](../adr/0004-observation-vs-verdict.md)

### M-1.7 재시도

| 상황 | 처리 |
|---|---|
| 타임아웃 · 5xx | 지수 백오프(10분 → 1시간)로 최대 3회. 3회 실패 시 `undetermined/timeout` 확정 |
| 4xx (404 제외) | 재시도 없이 `undetermined/timeout` |
| DNS 실패 | 재시도 없이 `undetermined/dns_fail`. 3주 연속이면 마스터 점검 알림 |

## M-2 · 응답 정확도 (Layer 2 · 3)

문항 원문과 채점 지침은 [`K04-question-sets.md`](./K04-question-sets.md).

> **M-2는 「K10 심리측정 기반 측정 설계」에 따라 재작성되었다.** 핵심 변경: ① 판정을 값이 아니라 **분포**로 저장 ② 평균이 아니라 **Floor**를 보고 ③ 골격/세부 분리 ④ 실패에 **증상군** 부여. 근거는 [ADR-0006](../adr/0006-distribution-over-score.md).

### M-2.0 저장의 원칙 — 집계는 저장이 아니다

`item_results` 는 **반복 회차별로** 판정을 저장한다. 집계는 조회 시점에 한다. 집계된 값에서 분포를 복원할 방법은 없으므로, 이 원칙을 어기면 데이터가 영구히 손상된다.

### M-2.1 지명 질문 — 12문항

4단계 판정을 **골격·세부 두 축으로 분리**해 회차마다 기록한다. **판정은 사람이 한다** (Layer 3의 Judge 예외는 M-2.8).

| 축 | 묻는 것 |
|---|---|
| `skeleton_match` | 절차의 뼈대가 맞는가 (신청 → 스티커 → 배출) |
| `detail_match` | 금액·창구·기한·요일이 맞는가 |

| skeleton | detail | 진단 | 조치 |
|---|---|---|---|
| ○ | ○ | 정상 | — |
| ○ | ✕ | **세부 표류** — 정본은 있으나 낡거나 불완전 | 해당 항목 갱신 |
| ✕ | — | **골격 부재** — 정본 자체가 없거나 도달 불가 | 정본 신규 작성 |
| 회차 간 진동 | — | **불안정** — 반복마다 뼈대가 달라짐 | 상충 정보원 정리 |

4단계 판정(`정확 / 부분정확 / 부정확 / 부재`)은 유지하되, 두 축과 함께 기록한다.

| 판정 | 조작적 정의 |
|---|---|
| `정확` | 핵심 사실이 맞고, 그대로 따라 해도 문제가 없다 |
| `부분정확` | 방향은 맞으나 세부(금액·기간·부서·절차)가 틀리거나 빠졌다 |
| `부정확` | 핵심 사실이 틀렸다. 그대로 따라 하면 잘못된 행동을 하게 된다 |
| `부재` | 모른다고 답했거나, 우리 지역이 아닌 일반론만 말했다 |

경계 사례의 처리:

- **일반론만 말한 경우** → `부재`. "대부분의 지자체에서는…"은 우리 지역에 대한 답이 아니다.
- **맞지만 오래된 정보** → `부분정확`. 시점이 다르면 세부가 틀린 것과 같다.
- **맞는데 확신도가 낮다고 표시** → 판정은 내용으로만 한다. 확신도는 별도 기록.
- **일부만 답한 경우(3개 물었는데 1개)** → `부분정확`.

### M-2.2 무지명 질문 — 8문항

**등장 여부**를 먼저 본다. 등장했으면 내용 정확도를 2단계(`맞음`/`틀림`)로 본다.

- 문항당 5곳을 추천받으므로 **총 슬롯은 8 × 5 = 40**.
- `unnamed_appearances` 는 우리 단위가 그 40개 슬롯 중 몇 번 등장했는지다.
- **최소 3회 반복**한다. LLM은 같은 질문에 다른 답을 내므로 1회 관측은 측정이 아니다.

### M-2.3 반복과 구간

| 레이어 | 최소 반복 |
|---|---|
| Layer 2 지명 | 1회 (참여 부담 고려) |
| Layer 2 무지명 | **3회** |
| Layer 3 전체 | 문항당 **5회 이상** |

결과는 점 추정이 아니라 **구간**으로 제시한다. `"등장률 12%"` 가 아니라 `"등장률 8~17% (5회 반복, 95% 구간)"`.

### M-2.3.1 3대 지표 — Distribution · Drift · Floor

| 지표 | 정의 | 산출 |
|---|---|---|
| **Distribution** | 반복 간 판정 변동 | 문항별 R회 판정의 분포 |
| **Drift** | 조건 간 변동 | 조건 축(M-2.7) 교차 시 판정 변화 |
| **Floor Risk** | **최악 응답의 위험 등급** | 아래 |

#### Floor Risk — 평균하지 않는다

R회 중 **가장 나쁜 응답**으로 등급을 매긴다.

| 등급 | 조건 |
|---|---|
| `critical` | 1회라도 **작화** — 없는 제도·창구·기한을 있다고 안내 |
| `high` | 1회라도 `부정확` (따라 하면 잘못된 행동) |
| `moderate` | 최악이 `부재` |
| `low` | 최악이 `부분정확` 이상 |

**작화가 최상위인 이유** — `부재`("모르겠습니다")는 주민을 공식 창구로 보낸다. 불편하지만 안전하다. 그럴듯한 오답은 없는 창구로 보내고 헛걸음을 만든다. **더 매끄러운 답이 더 큰 피해를 만든다.**

> **Layer 2의 지명 1회 측정은 Floor Risk를 산출하지 않는다.** R=1이면 최악이 곧 유일한 값이다. 화면에 표시하지 않고 "1회 관측이므로 참고값"임을 명시한다.

### M-2.3.2 실패 증상군

`부분정확` 이하의 판정에는 증상군을 부여한다. **판별 규칙이 없는 증상명은 붙이지 않는다.**

| 증상 | 판별 규칙 | 처방 (Layer 4) |
|---|---|---|
| `confabulation` 작화 | 존재하지 않는 제도·창구·기한을 구체적으로 명시 | 정본 신설 + 명시적 부재 선언 |
| `stale_fact` 정보 고착 | 과거 시점 정보로 고정 (반복해도 같은 옛 값) | 정본 갱신 + 갱신일자 구조화 표기 |
| `generic_drift` 일반론 표류 | 지역 고유 정보 없이 일반 서술만 | 지역 고유 서술 보강 · 엔티티 명시 |
| `cross_unit` 타 단위 혼입 | 다른 지자체 정보를 우리 것으로 제시 | 동명·유사명 구분 신호 강화 |
| `hypersensitivity` 표현 민감 | **M-2.6 강건성 검사에서만 판별** | 동의 표현 대응 정본 (FAQ 확장) |
| `unstable_skeleton` 골격 진동 | **R ≥ 3 에서만 판별** — 회차 간 뼈대 불일치 | 상충 정보원 정리 · 단일 출처 확정 |

이 표가 P1 진단의 「무예산 조치 목록」과 「스키마 처방」의 도출 근거다. **측정이 처방으로 자동 번역되는 것이 증상군의 값어치다.**

### M-2.4 측정 조건 — 필수 기록

조건 없는 관측은 **저장되지 않는다**(DB NOT NULL).

| 항목 | 필수 | 비고 |
|---|---|---|
| AI 서비스명 | ✅ | ChatGPT · Claude · Gemini … |
| 모델 버전 | 확인 가능한 경우 | Layer 3은 필수 |
| 측정 일시 | ✅ | |
| **웹 검색 사용 여부** | ✅ | 아래 참조 |
| 언어 | ✅ | 기본 `ko` |
| 계정 개인화 여부 | 권장 | 과거 대화·메모리 영향 |
| 반복 횟수 | ✅ | |

> **웹 검색은 반드시 끈다.**
>
> 검색을 켜면 AI가 그 자리에서 찾아보므로 대체로 정확해진다. 그러면 **측정이 되지 않는다.** 끈 상태가 AI가 우리 지역을 "원래 어떻게 알고 있는가"이고, 그것이 개선 대상이다. 켠 상태의 관측은 저장하되 **별도 조건으로 분리**하고 같은 표에 넣지 않는다.

### M-2.5 Layer 3의 정직성 요건

API로 측정한 결과는 **소비자 앱에서 사용자가 보는 결과와 다를 수 있다** — 모델 버전, 시스템 프롬프트, 검색 연동, 개인화가 다르기 때문이다.

- 리포트에 이 차이를 명시한다.
- **Layer 2(사람이 앱에서 잰 값)와 Layer 3(API 값)을 같은 표에 넣지 않는다.**
- 둘을 비교하는 별도 뷰는 가능하되 "다른 측정"임을 화면에 표시한다.

### M-2.6 문항 강건성 검사 — 채택 조건

**모든 문항은 채택 전에 이 검사를 통과해야 한다.** 통과하지 못한 문항은 명세에 넣지 않는다. → [ADR-0007](../adr/0007-questions-are-instruments.md)

| 변형 축 | 내용 | 예 |
|---|---|---|
| `punct` | 종결 부호 | `…버리나요?` / `…버리나요.` |
| `polite` | 존대 수준 | `알려주세요` / `알려줘` |
| `order` | 절 순서 | `수수료와 신청 방법` / `신청 방법과 수수료` |
| `frame` | 화자 프레임 | (없음) / `주민입니다.` |

```
같은 단위 · 같은 조건에서 원문 + 변형 4종을 각각 R회 반복
→ 변형 간 판정 분포의 차이를 산출
→ 임계값 초과 시 '민감 문항'으로 표시
→ ① 문구를 다듬어 재검사 또는 ② 명세에서 제외
```

**임계값이 정해지기 전에는 어떤 수치도 공표하지 않는다.** 임계값은 착수 시 파일럿으로 정한다. 검사 결과는 방법론 페이지에 **문항별로 공개**한다.

### M-2.7 조건 축 (Layer 3 전용)

출력은 프롬프트·시스템·맥락의 함수이므로, 조건을 흔들어 민감도를 잰다.

| 축 | 값 |
|---|---|
| `web_search` | off (기본) / on |
| `language` | ko (기본) / en / zh / ja |
| `actor` | 없음 (기본) / 주민 / 방문검토자 / 투자검토자 |

**전 조합을 돌리지 않는다.** 기본 조건(off · ko · 없음)을 기준으로 두고 **한 번에 한 축만** 바꾼다. 조합 폭발을 막고 해석을 명확히 한다.

`web_search=on` 조건에서는 **인용 출처를 함께 기록**한다. 공식 누리집이 인용된 비율은 P2 정본 사업의 KPI가 되며, **관측일 뿐 보장이 아니다**(NG-2).

### M-2.8 Judge 모델 (Layer 3 한정)

Layer 2의 채점은 **사람만** 한다 — 참여자가 직접 채점하는 것이 그 층의 의미다.

Layer 3은 문항 20 × 반복 5 × 조건 4 × 단위 N을 사람이 전부 채점할 수 없다. Judge 모델을 쓰되 **다섯 조건을 모두** 지킨다.

1. 응답 생성 모델과 Judge 모델을 **분리**한다. 같은 모델을 쓰지 않는다.
2. 판정 기준은 **사람이 쓴 것**(`K04` §3.2)을 그대로 준다. Judge에게 기준을 만들게 하지 않는다.
3. 표본의 일정 비율을 **사람이 교차채점**하고 일치도를 산출한다.
4. **일치도를 리포트에 기재**한다. 기준 미만이면 그 회차 결과를 공표하지 않는다.
5. Judge 모델·버전을 기록한다. **Judge도 드리프트한다.**

## M-4 · 지역 페르소나 진단 (Layer 3 전용 · v1 후반)

무지명 질문은 **"등장하는가"** 를 본다. 페르소나 진단은 **"어떻게 지각되는가"** 를 본다.

```
이상 페르소나  ← 시정 비전 · 슬로건 · 중점 시책 · 브랜드 선언 (공식 문서에서 추출)
지각 페르소나  ← "○○시는 어떤 도시인가?" 등 개방형 문항 R회 반복 → 서술 집계
불일치        ← 두 서술의 핵심 속성 대조
```

| 산출 항목 | 내용 |
|---|---|
| 지각 핵심 속성 | AI 서술에서 반복 등장하는 속성 상위 N개 |
| 이상 대비 결손 | 이상에는 있으나 지각에 없는 속성 |
| 이상 대비 왜곡 | 이상과 반대로 지각되는 속성 |
| 고유 서사 강도 | 인접·유사 지자체 서술과의 차별도 |
| 안정성 | 반복 간 서술 일관성 (Distribution) |

**설계는 Single-Subject Design** — N=1 단위, 반복 측정, 개입 전후 비교. 이 설계가 *"표본이 하나인데 어떻게 통계인가"* 라는 질문에 대한 답이며, 지자체 한 곳을 대상으로 하는 P1 상품의 방법론적 근거가 된다.

> **이 진단은 평가가 아니다.** "AI가 이렇게 지각한다"는 관측이지 "이 도시는 매력이 없다"는 평가가 아니다. 리포트 문안에서 이 구분을 흐리면 NG-1과 LC-3을 동시에 위반한다.

개방형 서술의 채점은 4단계 판정처럼 기계적으로 되지 않는다. 따라서 **M-4는 Layer 3(유료·사람 감독)에서만** 수행하고 무료 Layer 2에는 넣지 않는다.

## M-3 · 명세 버전 관리

`method_version` 이 관리하는 것:

- 문항 세트 — **8블록 값의 묶음** (`Actor · Situation · Task · Knowledge · Workflow · Format · Language · Output`)
- 판정 기준 (4단계 정의, 골격/세부 축, Floor Risk 등급, 증상군 판별 규칙)
- 반복 횟수 · 조건 축
- 강건성 검사 임계값
- 대상 AI 수집기 목록
- robots 해석 규칙

블록 하나만 바뀌어도 버전이 오르되, **어느 블록이 바뀌었는지가 기록**되므로 부분 비교가 가능하다. 이것이 문항을 자연어가 아니라 블록으로 저장하는 실제 이유다. → [ADR-0007](../adr/0007-questions-are-instruments.md)

**버전이 다른 관측은 기본적으로 비교하지 않는다.** 비교 쿼리는 버전을 명시적으로 고정하거나 환산 계수를 거친다.

명세 변경 시 **이행 기간 동안 두 버전을 병행 측정**해 환산 계수를 산출한다. 병행 측정 없이 버전을 올리면 그 시점에서 시계열이 끊긴다.

## 알려진 한계 — 공개 문서에 그대로 싣는다

1. **1회 관측은 측정이 아니다.** LLM은 비결정적이며, Layer 2의 지명 1회 관측은 참고값이다.
2. **`Allow`/`Disallow` 경로 우선순위를 판정에 반영하지 않는다.** 루트 전면 차단만 본다.
3. **robots.txt 준수는 크롤러의 자율이다.** 개방이라고 해서 실제로 수집되었다는 뜻은 아니고, 차단이라고 해서 모든 수집기가 물러난다는 뜻도 아니다. 우리가 측정하는 것은 **기관이 무엇을 선언했는가**이지 **실제로 수집되었는가**가 아니다.
4. **AI가 무엇을 근거로 답하는지 우리는 알 수 없다.** 응답 정확도와 도메인 접근성 사이의 인과는 이 측정으로 증명되지 않는다. 상관을 인과로 서술하지 않는다.
5. **판정 불가는 원인을 말하지 않는다.** 무엇이 막고 있는지(설정·보안장비·속도 제한)는 진단 없이 판별되지 않는다.
6. **문항의 강건성은 검사된 범위 안에서만 보장된다.** 우리가 검사한 변형 축은 4종이며, 검사하지 않은 축(문항 순서, 대화 이력, 시스템 프롬프트)에 대한 민감도는 알지 못한다.
7. **구성 타당도는 아직 확보되지 않았다.** 우리는 "AI가 부정확하게 답한다"는 것을 잴 수 있지만, 그것이 "주민이 실제로 피해를 본다"와 대응하는지는 검증되지 않았다. → `K10` §9
