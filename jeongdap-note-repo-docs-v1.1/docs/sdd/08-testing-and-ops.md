# SDD 08 — 테스트·CI·운영

## 1. 테스트 피라미드
| 수준 | 대상 | 도구(예) |
| --- | --- | --- |
| 단위 | `lib/domain`: 정규화·답안지·판정·통계(부트스트랩·윌슨·κ)·세트 검증·의견 질문 감지·글자 혼용 감지 | Vitest |
| 통합 | 회차(가짜 어댑터) → 판정 → 집계 → 엠바고 → 발행 → 재검증 | Vitest + 로컬 Supabase |
| RLS | `roles-and-permissions.md` 매트릭스의 모든 칸 | SQL 테스트(pgTAP 등) 또는 역할별 클라이언트 |
| E2E | 시민·지자체·판정자·원어민 검수자·운영 흐름 | Playwright |
| 접근성 | 자동 점검 + 화면 낭독기 수동 | axe 계열 + 수동 |
| 부하 | 발표일 공개 페이지, `/api/check` | k6 등 |

필수 회귀 케이스: 인천 중구 검색 → 승계 안내 / 대정 오일장 “매주 토요일” → nofact / 의견 질문 거부 / 중복 투표 거부 / 고정 세트 수정 거부 / 판정자 실명 미노출 / 다른 지역 포털 차단 / 글자 혼용 승인 거부 / 미성년 역할 거부 / 정본 변경 60초 반영.

## 2. 환경
| 환경 | 데이터 | 비고 |
| --- | --- | --- |
| local | 시드 + 예시 데이터 허용 | `supabase start` |
| staging | 익명화·예시 허용 (`example` 배지 강제) | 미리보기 배포 |
| production | 예시 금지 (빌드 플래그) | 승인 배포 |

## 3. CI 순서
lint → typecheck → unit → RLS → integration → build → e2e(스테이징) → a11y → 번들 크기 → 배포 승인.

## 4. 관측
- 로그: 요청 ID·작업 ID·round_id 상관관계.
- 지표: 회차 진행률·실패율·서비스별 지연·비용, 판정 대기열, 재검증 지연, LCP.
- 경보: 비용 80%, 실패율 5%, DLQ>0, 재검증 실패, 엠바고 기한 24시간 전.

## 5. 운영 절차 (런북 요약)
1. 회차 전: 서비스 약관 확인 → 세트 검증·고정 → 사전 등록 공개 → 비용 상한 설정.
2. 회차 중: 진행률·DLQ 감시, 카나리 급변 시 운영 판단 기록.
3. 회차 후: 사람 판정·조정 → κ 확인(0.8 미만이면 규칙 검토) → 집계 → 엠바고 → 지자체 사실 확인 → 발행.
4. 발행 후: 리포트 생성 확인, 정정 요청 처리(정정 공지).
