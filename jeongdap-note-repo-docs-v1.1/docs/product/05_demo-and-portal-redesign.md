# 정답노트 데모·지자체 포털 수정 설계 — 방법론 v1.0 반영

Oct 8, 2026 · ㈜디지털미디어네트워크 · 개발용 v1.0 · 대상: 모두의 정답노트 데모 v0.7 · 수원 지역 문화 데모 · 정답노트 등록부·포털

## 1. 요약

> 데모와 포털을 방법론 v1.0에 맞춘다. **공개 화면은 두 지표와 밴드 지도**로, **지자체 포털은 정비 사건 등록부**를 중심으로, **시민 화면은 신고판에 확인단**을 더한다. 서비스 매트릭스와 판정 배지는 출처 4단과 “끊긴 단” 표시로 바꾼다.

| 화면 | 지금 (v0.7) | 바꾼 뒤 |
| --- | --- | --- |
| 공개 홈 | 지역 선택 → 서비스별 판정 매트릭스, 정확도 배지 | **전국 밴드 지도** + 두 지표(공식 근거율·피해 위험 건수) + 생활 영역별·언어별 분포. 서비스 비교는 “관찰 측정” 탭에 분포로만 |
| 단위 페이지 | 질문별 서비스 판정 | 자기 값만 — 공식 근거율, 출처 4단에서 **끊긴 단**, 구간 이동, 정비 사건 목록, 개선 사례(동의 시). 다른 단위 값 없음 |
| 지자체 포털 | 정책 사실 입력, 통지함, 참여 사업 | **정비 사건 등록부**(핵심), 대조 쌍 3건, 이번 주·분기·예산 목록, 자체 점검표, 협조 요청 서식, 선언표, 행사 일정, 검색 콘솔 연결 |
| 시민 | 신고판 | 신고판 + **확인단 작업대** (2인 독립 배정, 위약 섞기, 정확도) |
| 운영 | 확인 데스크 | 회차 관리(사전 등록·블록·판본 기록), 판정 작업대(전수·20% 교차), 통지·확인 기간, 밴드 경계·공개 승인 |

**지표 이름:** 화면에는 한글 서술명만 쓴다 — “공식 근거율”, “피해 위험”, “검색에 뜸 → AI가 읽음 → 첫 근거가 됨 → 내용이 맞음”, “공식 근거 많음 / 보통 / 적음”.

## 2. 공개 화면 수정

### 2.1 홈 — 전국 밴드 지도

| 요소 | 설계 |
| --- | --- |
| 지도 | 226개 기초·17개 광역을 3구간 색으로. 광역/기초 토글. 회색 = 측정 문항 부족 |
| 밴드 범례 | “공식 근거 많음 · 보통 · 적음” + 경계값(예: 70% · 40%)과 산식 링크 |
| 구간 이동 | 지난 회차 대비 ↑↓ 표시. 클릭 시 정비 사건 등록 여부 |
| 두 지표 | 전국 공식 근거율(공급 공백 제외 분모 명시), 피해 위험 건수(재난·안전 제외 명시) |
| 분포 패널 | 생활 영역별 5개, 언어별 4개 — 막대, 순위 없음 |
| 회차 표시 | “2027년 3월 회차 · 측정 3월 2·3·4일 · 모델 판본 ○○” |
| 금지 | 단위 정렬·검색 순위, 밴드 안 순서, “최하위” 류 표현 |

### 2.2 단위 페이지

| 블록 | 내용 |
| --- | --- |
| 머리 | 단위명, 밴드, 구간 이동, 회차 |
| 공식 근거율 | 값 + 문항별 0\~3 분포 + 생활 영역별·언어별 |
| 끊긴 단 | 출처 4단 깔때기 — 검색에 뜸 → AI가 읽음 → 첫 근거가 됨 → 내용이 맞음. 가장 많이 끊긴 단을 강조 |
| 피해 위험 | 건수만 (문항·내용은 포털에서) |
| 정비 사건 | 등록된 사건 목록(코드·날짜·전달 확인), 개선 사례(동의 시 전후 비교표) |
| 참여 | “이 지역 포털 열기”(기관), “AI 답 신고”(시민) |
| 없는 것 | 다른 단위의 값, 순위, 서비스별 값 |

### 2.3 관찰 측정 탭

다른 AI 서비스의 분기 소표본 결과를 \*\*서비스 이름 없이 “서비스 A·B·C”\*\*로, 공식 근거율 분포만 보여 준다. 정밀 측정(API 기준)과 합산하지 않는다는 문구를 고정한다.

### 2.4 지역 문화 트랙

기존 트랙 소개·신고·집계는 유지하되, 집계 화면의 “근거 유형·원인 네 유형”을 **출처 4단과 공급 공백**으로 통일한다. 수원 사전 관측은 7장.

## 3. 지자체 포털 — 정비 사건 등록부 중심

### 3.1 홈 — 다음 할 일

이번 주(0원) · 이번 분기 · 다음 예산 세 묶음으로 4축 분류 결과를 보여 준다. 각 항목은 **끊긴 단 · 통제권 · 난이도 · 정비 유형 코드**를 붙이고, 누르면 등록부 작성 화면으로 간다.

### 3.2 정비 사건 등록부 (핵심 기능)

| 단계 | 화면 | 입력 (타이핑 최소) |
| --- | --- | --- |
| ① 대상 고르기 | 측정에서 인용된 자기 페이지 목록 (끊긴 단별) 또는 주소 붙여넣기 | 목록에서 선택 |
| ② 무엇을 했나 | 정비 유형 코드 칩 — F 본문 형식 · T 제목·첫 문단 · Q 요약 · D 중복 정합 · U 갱신 · A 고정 주소 · S 사이트 접근성 · L 협조 요청 · N 신규 작성 · M 소개 메시지 · E 행사 페이지 · P 사업 페이지 · G 다국어 · R 포털 등재 · W 공개 지식 연결 | 칩 선택 (복수) |
| ③ 언제 | 게시·수정 일시 (기본: 지금) | 날짜 선택 |
| ④ 증빙 | 시스템이 전후 본문 해시·화면을 자동 수집 | 없음 |
| ⑤ 전달 확인 | 자동 — 도구 반환 목록에 새 제목·요약으로 보이는지, 검색 콘솔 재색인(연결 시) | 없음 — 상태 표시 (대기·확인됨·미확인 N일) |
| ⑥ 다음 회차 | 전달 확인 뒤 첫 회차에서 전후 비교표 자동 생성 | 없음 |
| ⑦ 공개 | “개선 사례로 공개 동의” 토글 | 토글 |

- 등록부는 **연결 문항**(이 페이지에 걸린 고정 패널 문항)을 자동으로 붙인다.
- 대기 중인 페이지의 본문 해시가 바뀌면 “미등록 변경”을 표시하고 등록을 권한다.
- 등록 사건 수, 전달 확인 수, 전후 비교 완료 수를 포털 홈에 센다.

### 3.3 함께 있는 화면

| 화면 | 내용 |
| --- | --- |
| 대조 쌍 3건 | 같은 주제·같은 도메인에서 읽힌 페이지와 안 읽힌 페이지 — 첫 장 |
| 끊긴 단 상세 | 문항별 출처 4단, 인용 대조 결과(정합·낡음·내부 상충·원인 미확정·근거 없음) |
| 피해 위험 | 고위험 문항별 가장 나쁜 회차 내용(비공개), 2출처 원장, 공식 간 상충 |
| 자체 점검표 | 공급 상태 목록을 행안부 가이드라인 항목에 정렬 — 내려받기 |
| 협조 요청 서식 | 기초 → 광역 / 연결기관. 대상 페이지·불일치·근거·요청 사항 자동 채움 |
| 정본·선언표 | 정책 사실 정본(기존), 자기 소개 선언표(알릴 요소·알리지 않을 요소·낡은 요소), 행사 일정(D-30·D-7·D+7 점검 예약) |
| 자료 연결 | 검색 콘솔 자료 제공 동의·연결 (수요 배분·색인 확인용) |
| 통지함 | 회차별 통지, 14일 확인 기간, 확인함·이견·공개 동의 |

## 4. 시민 참여 화면

### 4.1 신고판 (유지 + 수요 집계)

기존 신고 흐름(접수 → 재현 → 원인 → 기관 통지 → 회신 → 집계)을 유지하고, 신고 질문을 **생활 영역 × 기능 층**으로 자동 분류해 운영 화면의 수요 집계에 보낸다. 신고자에게 재현 결과와 처리 단계를 돌려준다.

### 4.2 확인단 작업대 (신규)

| 요소 | 설계 |
| --- | --- |
| 가입 | 신고판 사용자 중 신청 → 30분 온라인 교육 → 연습 5건(위약 포함) 통과 |
| 작업 카드 | 질문 · AI 응답 원문(단위명·개인정보 가림) · 추출 결과(“첫 근거: ○○ 누리집” 등) → **맞음 · 다름 · 판단 불가** 세 버튼 |
| 배정 | 같은 건을 2인에게 독립. 10%는 위약 문항. 한 사람에게 같은 단위가 몰리지 않게 |
| 피드백 | 2인 일치 여부와 운영팀 판정을 뒤에 알려 줌. 정확도(위약 기준) 표시 |
| 보상 | 건수 기준 소액 또는 관람권. 추첨 아님 |
| 공개 | 회차 집계에 “시민 확인 ○건 · 2인 일치 ○% · 운영팀 일치 ○%” |
| 접근성 | 모바일에서 한 건 1–2분. 키보드 조작·대비 |

## 5. 운영 화면

| 화면 | 기능 |
| --- | --- |
| 회차 관리 | 회차 생성(분기), 사전 등록 공개본 생성(문항 해시·기대표·귀속표·규칙), 측정 블록·날짜, 모델·도구 판본 기록, 고정 기준 문항 시계열과 변동 표시 |
| 문항 은행 | 묶음·층·언어·보류 표시, 작성자 식별자·선행 노출, 해시 잠금, 위약 문항 |
| 판정 작업대 | 자동 판정 결과 → 사람 전수(등장·귀속·위험·불일치·근거 없음) → 20% 교차 배정(시민 확인단·운영팀) → 일치도 집계 |
| 인용 대조 | 수집 페이지(해시·최종 수정)와 핵심 값 대조, 판정 분류, 시점 불일치 표시 |
| 통지·확인 | 단위별 통지문 자동 생성(이번 주·분기·예산 목록·자체 점검표·협조 서식 동봉), 14일 기간 관리, 이견 처리 |
| 밴드·공개 | 경계 설정(사전 공개 잠금), 밴드 계산, 구간 이동, 공개 승인(확인 기간 종료 확인), 재난·안전 비공개 분리 |
| 등록부 감시 | 전 단위 등록 사건, 전달 확인 상태, 미등록 변경 감지, 전후 비교 생성, 효과 추정(등록 30건·10곳 조건 표시) |
| 수요 집계 | 신고 분류 비중, 검색 콘솔 자료(동의 단위), 층 배분 제안 |
| 감사 | 모든 변경의 감사 로그, 보류 문항 접근 기록, 제3자 열람 요청 처리 |

## 6. 데이터 모델 변경

| 테이블 | 변경 | 핵심 열 |
| --- | --- | --- |
| `round` (신규) | 회차 | 회차 id, 분기, 사전 등록 공개본 해시, 블록 날짜, 모델·도구 판본, 경계값, 공개 승인 시각 |
| `question` (변경) | 문항 은행 | 묶음·생활 영역·기능 층·언어·사다리 단계·보류 여부·작성자·선행 노출·해시 |
| `expect_table` (신규) | 기대표·귀속표 | 문항 × 단위 × 선언(대표 자산·나올 만함·약함·해당 없음) × 선언자 2인 × 근거 출처 · L2 귀속 단위 목록 · 해시 |
| `response` (변경) | 회차별 응답 | 회차·블록·문항·언어·조건·응답 원문(비공개)·도구 반환 목록·인용 URL |
| `judgement` (변경) | 판정 | 출처 1\~4단, 등장·귀속, 위험 수준, 인용 대조 분류, 판정자(자동·운영·확인단), 교차 일치 |
| `verify_task` (신규) | 확인단 작업 | 응답·배정 확인자 2인·선택·위약 여부·일치 여부·운영팀 판정 |
| `supply_audit` (신규) | 공급 상태 | 페이지·형식·상충·낡음·갱신 표기·고정 주소·가이드라인 항목 |
| `repair_event` (신규, 핵심) | 정비 사건 | 단위·페이지·코드\[\]·일시·전 해시·후 해시·전달 확인(방식·시각)·연결 문항\[\]·공개 동의·미등록 변경 플래그 |
| `notice` (변경) | 통지 | 회차·단위·발송·확인 기한·확인함·이견·공개 동의 |
| `band` (신규) | 밴드 | 회차·단위·공식 근거율·분모·밴드·구간 이동·사유(등록 사건 유무) |
| `demand_stat` (신규) | 수요 | 회차·단위·층·신고 비중·검색 콘솔 비중 |

**규칙:** `response.raw`와 수집 페이지는 비공개 저장소. 공개 API는 `band`·집계·`repair_event`(동의분)만 낸다.
